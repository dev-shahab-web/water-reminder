# Play reviews and app updates

Android reviews and updates use `src/core/config/engagement-config.ts`. The native
bridge and WorkManager worker are generated by
`plugins/water-reminder-engagement/withWaterReminderEngagement.js`; edit the plugin
sources, then run Expo prebuild and rebuild the app. Expo Go cannot run this bridge.

## Review reminders

- First eligible notification: five full days after Android's `firstInstallTime`,
  after onboarding. Updating the app does not reset the installation age.
- Repeat: at least seven days after the last delivered reminder, opening the Play
  listing, or choosing **Maybe later**. Missed weeks do not produce a burst.
- A silent notification opens `/feedback`, which offers an honest review on Google
  Play, **I've already reviewed**, **Don't remind me**, and **Maybe later**.
- Google Play does not report whether a person posted a review. Only the user's
  confirmation marks it reviewed. Opening the listing merely snoozes reminders.
- Confirmation or opting out cancels the current notification and stops future
  reminders. Users can explicitly enable them again in Settings.
- Review prompts never filter by rating, reward reviews, or gate app features.

## Updates

The app uses Google's Play In-App Updates library (`app-update:2.1.0`). It checks
after onboarding, on foreground entry, and approximately every 12 hours through a
unique WorkManager job. Google decides availability for the installed package,
account, device, version code, and release track; staged rollouts may differ.

When a newer version is available:

1. Post one notification for that version, opening `/updates`.
2. Show a themed update dialog on Home or Settings while the app is foregrounded.
   It does not interrupt onboarding, logging screens, or purchase screens.
3. **Update now** launches Google's consent flow, preferring a flexible download.
   Immediate updates or the Play listing are used when required by availability.
4. Show download progress. Once downloaded, offer **Restart to update** and a
   separate ready-to-install notification. The app only requests completion after
   the user chooses to restart. An immediate flow follows Google's own consent UI.

**Maybe later** dismisses the dialog for 24 hours for that release and stage.
A newer release or a completed download can prompt again. Settings → **App updates**
always provides a manual check. Network/Play failures show an unavailable state,
never an unverified “up to date” result. A new release number is not hardcoded or
scraped from a website.

## Notifications and local state

Review reminders and update notifications have independent Settings switches,
separate Android channels, and dedicated IDs. They are enabled by default after
onboarding but require Android notification permission. Initialization does not
display a permission prompt. Explicitly enabling a switch can request permission.
Turning off update notifications leaves in-app checks and dialogs available.
Hydration reminders and optional Plus promotions retain their own controls.

The native preferences file `water_reminder_engagement` stores configuration,
reminder choices and timestamps, review confirmation, and last notified version
codes. Dialog snoozes use MMKV. Review content is never read by the app. No
developer push service or hydration data is involved in update checks.

WorkManager delivery is approximate: Android Doze, battery restrictions, disabled
channels, notification permission, or force-stop can delay/prevent notifications.
This is periodic discovery, not an immediate push when a release is published.

## Configuration

| Setting                        | Default                    | Purpose                                          |
| ------------------------------ | -------------------------- | ------------------------------------------------ |
| `playPackage`                  | `com.shahab.waterreminder` | Production Play listing for reviews and fallback |
| `review.firstReminderDays`     | `5`                        | Minimum installation age                         |
| `review.repeatDays`            | `7`                        | Minimum time between review prompts              |
| `updates.backgroundCheckHours` | `12`                       | Periodic background checks                       |
| `updates.promptSnoozeHours`    | `24`                       | Per-release/stage dialog snooze                  |
| `review/updates.title/body`    | See config                 | Notification wording                             |

Native cadence values are bounded to 1–365 days and the worker interval to 6–24
hours. The Settings reminder description reads the same config.

## Google Play release verification

A sideloaded preview can verify screens, persistence, scheduling and errors, but
does not establish a real Play update. Before release, follow Google's
[in-app update test procedure](https://developer.android.com/guide/playcore/in-app-updates/test)
using internal app sharing or a testing track:

1. Install an older build via Google Play with the account that owns the app.
2. Make a compatible build with a higher version code available to that account.
   Application ID and signing requirements must match Google's test method.
3. Verify the update notification and cold/warm notification routing; check that
   reopening the app does not post another notification for the same version.
4. Verify the Home/Settings dialog, **Maybe later** persistence, consent decline,
   download progress, leaving/returning to the app, and **Restart to update**.
5. Confirm the new version preserves hydration records and reminder preferences,
   clears stale update UI, and no longer reports the installed release as new.
6. Exercise notification permission/channel denial, offline checks and staged
   rollout eligibility. Do not publish a public release solely for this test.

Review cadence boundary tests are in `ReviewCadenceTest.kt`; run after prebuild:

```sh
cd android
./gradlew :app:testDebugUnitTest --tests com.shahab.waterreminder.engagement.ReviewCadenceTest
```

The JS service and update-card tests cover explicit consent, store failures,
deduplicated checks, Play outages, snoozes, and restart actions.
